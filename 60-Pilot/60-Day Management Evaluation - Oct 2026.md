# 60-day controlled internal development evaluation — October 2026

**Program objective:** produce decision-grade evidence for one or two feasible internal automation pilots and for whether an ongoing software development capability is justified. This is not a five-project delivery commitment.

| Period | Focus | Acceptance artifact |
|---|---|---|
| Days 1–15 | Confirm sponsor, workflow scope, baselines, data access, priority and safeguards | Signed measurement and permission plan |
| Days 16–30 | Refine minimum solution; validate data and exceptions in a controlled environment | Test results, failures, development effort |
| Days 31–45 | Timed operational trials and user acceptance | Before/after observations, accuracy, adoption, exception log |
| Days 46–60 | Evaluate lifecycle cost, value, controls and next stages | Management recommendation and go/no-go options |

## Pilot authorization requested
- Agree explicit development/testing time and any resource ceiling.
- Nominate a responsible operational sponsor and relevant user representatives.
- Select one or two pilots using readiness, expected value, risk and measurability.
- Approve only policy-compliant data access; require IT/SAP participation for integrations.
- Set an end-of-pilot review with the option to stop, revise, buy, outsource or continue.

## Day-60 decision framework
Use verified baseline and after-times, representative annual volumes, exceptions, user acceptance, tested transaction integrity, implementation effort and realistic maintenance/support costs. Separate operational capacity from demonstrable expense reduction. Do not attribute one RF/picking/counting gain to multiple projects. Do not assume cross-branch transfer without a separate site assessment.

A dedicated developer position remains a **future management decision**, supported only by demonstrated recurring work, sustained value and a continuity plan.
